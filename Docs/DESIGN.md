# Shift Magic Spell 기획 (2026-11-20, 5차 기준)

거대한 마우스 커서(손)가 키보드 위의 플레이어를 공격한다. 플레이어는 공격을 피하면서 **Shift로 키보드의 행·열을 돌려** 공격 단어를 한 줄로 맞추고, 완성된 단어가 마법이 되어 커서를 친다. 마지막 한 방은 **SHIFT**.
GitHub Game Off 2026(주제 SHIFT) 출품작이고, 마감은 한국시간 12월 2일 06:37(PST 12/1 13:37)이다.

- 온라인 기획서(4차까지): https://claude.ai/artifact/7U4LFHVGAxiAq9K9Bmjk3n
- 웹 프로토타입: `WebPrototype/shift-magic-spell-prototype.html` (5차 규칙 반영, 원본은 `WebPrototype/src/`)

> **5차에서 바뀐 것 (11/20):** 플레이 테스트에서 "Shift가 어디서 쓰이는지 핵심적으로 느껴지지 않는다"는 문제가 나왔다. 걸어가서 Space로 누르는 철자 맞추기가 기본 동작이었고, Shift는 여기저기 얇게 흩어져 있었기 때문이다. 그래서 **기본 동작 자체를 Shift(줄 돌리기)로** 바꿨다.
> - 글자 ±1 바꾸기, Space 등록, 입력 버퍼 → 없앰
> - Shift+방향키 = 서 있는 행·열 돌리기, 단어는 한 줄로 정렬하면 발동
> - 손은 키의 글자를 바꾸지 않는다. 피해 공격 위주 + 가끔 줄 섞기
> - 단어는 Shift 유의어 → 공격 단어(FIRE, MAGIC…), 완성하면 단어별 마법 연출
>
> **5차 추가 — 공격 슬롯 (11/20):** 왼쪽·오른쪽 판을 오갈 이유를 주려고, 완성한 단어를 바로 쏘지 않고 **반대편 판의 슬롯에 공격 블록으로** 담는다. 원하는 때 그 슬롯에 가서 Space로 쏜다. 모아서 연달아 쏘는 타격감(콤보)도 준다. (자세한 규칙은 5장)

## 2. 조작
| 입력 | 동작 |
| --- | --- |
| ↑ ↓ ← → / WASD | 한 칸 이동. 누르고 있으면 0.15초마다 반복 |
| **Shift + ← →** | 서 있는 **행**을 그 방향으로 한 칸 돌린다 (`ABCDE` → `EABCD`) |
| **Shift + ↑ ↓** | 서 있는 **열**을 그 방향으로 한 칸 돌린다 |
| Shift + 방향키 누르고 있기 | 0.24초마다 반복해서 돌린다 |
| **Space** | 공격 슬롯 칸 위에서: 담긴 공격 블록 발동 |
| SHIFT 칸 밟기 | 반대편 키보드 SHIFT 칸으로 순간이동 (쿨다운 2초, 도착 무적 0.5초) |
| R | 현재 페이즈 재시작 |
| P | 일시정지 (WebGL에서 ESC는 전체화면 해제라 쓰지 않는다) |

- 줄을 돌릴 때 플레이어는 **칸에 그대로** 있고 키만 발밑으로 지나간다. 그래서 같은 줄을 연달아 돌리기 쉽다.
- SHIFT 칸과 공격 슬롯 칸 위에서는 돌릴 수 없다(둘 다 줄 돌리기에서 빠지는 고정 칸이다).
- Shift를 누르고 있는 동안 돌릴 수 있는 행·열을 파랗게 보여 준다.

## 3. 판
키보드 2개(좌우), 각 29칸 = 글자 26 + 빈 키 2 + SHIFT 1. 텍스트 마스크로 정의한다.
```
왼쪽            오른쪽       (^ = SHIFT, _ = 빈 키, . = 칸 없음)
.IGMW_.         .WYFV_.
BRHNC_.         .KLOTPZ
YADSOT^         ^CNISRU
.ZLFEPJ         JDHEAQ.
.UXQKV.         ._BGMX.
```
- **공격 슬롯** 판마다 2칸: 판 바깥, SHIFT 칸의 반대쪽 끝(왼쪽 판은 1·2행 왼쪽 바깥, 오른쪽 판은 1·2행 오른쪽 바깥). 순간이동해 온 뒤 판을 가로질러 걸어가야 닿는다. 걸을 수 있지만 줄 돌리기에서 빠지는 고정 칸이다.
- 줄(행·열) = 그 행·열에서 SHIFT 칸을 뺀 칸들. 줄 돌리기와 단어 읽기가 같은 순서를 쓴다.
- 가장 긴 줄은 6칸(왼쪽 1~3행, 오른쪽 1~3행), 열은 최대 5칸.
- **글자는 바뀌지 않는다.** 판에는 늘 A~Z가 하나씩 있으므로 어떤 단어든 항상 만들 수 있다.
- 시작 배치 규칙: 어떤 단어도 시작부터 3글자 이상 한 줄에 맞춰져 있지 않을 것, 좌우 배치가 충분히 다를 것. `layoutRules.js`의 `check`로 검사, `generate-layouts.js`로 새 배치를 만들 수 있다.
- 데이터 모델: 칸마다 키 객체 `{id, letter}`. 줄 돌리기는 키 객체가 칸 사이를 옮겨 다닌다.

## 4. Shift = 줄 돌리기 (게임의 핵심)
| 누가 | 무엇을 | 언제 |
| --- | --- | --- |
| 플레이어 | 서 있는 행·열을 한 칸 돌림 | 언제든, 원하는 만큼 |
| 손(줄 섞기 공격) | 한 줄을 한 칸 돌림 | 가끔(쿨다운 7초), 예고 후 |

- 손과 플레이어가 **같은 동작**으로 싸운다. 손은 판을 섞고, 플레이어는 맞춘다.
- 연출(줄이 옮겨 가는 게 눈에 보여야 한다):
  - 키가 0.24초 동안 미끄러지고, 미는 쪽 끝부터 0.035초 간격으로 도미노처럼 차례로 움직인다.
  - 움직이는 키는 파란 테두리를 두르고, 뒤에 옅은 파란 잔상 두 장을 남긴다.
  - 끝을 넘은 키는 밖으로 빠져나가며 사라졌다가 반대편 끝에서 들어온다.
  - 플레이어가 돌리면 줄 전체에 파란 띠가 0.45초 깔리고, 그 위로 화살표(› 또는 ⌃)가 돌리는 방향으로 흐른다. 줄 양 끝 바깥에도 큰 화살표가 떠서 "이쪽으로 나가서 저쪽으로 들어온다"를 보여 준다.
  - Shift+방향키를 누르고 있어 미끄러지는 중에 다시 돌리면, 그 자리에서 이어서 움직인다(끊기지 않음).
  - 미끄러짐 시간·도미노 간격은 디버그 슬라이더로 조절한다.

## 5. 단어 = 공격 마법 (5차)
목표 단어를 **한 줄의 연속한 칸**에 맞추면(행은 왼→오, 열은 위→아래) 완성된다. 양쪽 키보드 어디에서든 된다.

### 5-1. 공격 슬롯 (5차 추가)
완성한 단어는 바로 쏘지 않고 **공격 블록**이 되어 **완성한 판의 반대편 판** 빈 슬롯으로 날아간다(0.5초 연출). 플레이어가 원하는 때 그 슬롯 칸에 가서 **Space**를 누르면 발동한다.

| 상황 | 결과 |
| --- | --- |
| 반대편에 빈 슬롯 있음 | 블록이 들어감. 손 HP는 아직 그대로 |
| 슬롯 칸에서 Space | 발동: 손에 글자 수만큼 피해, 손은 0.8초 멈춤(멈춤은 이때 걸린다) |
| 같은 판 슬롯을 1.5초 안에 연달아 발동 | **콤보**: 두 번째는 피해 +50% (예: FIRE 4 + BOLT 6) |
| 반대편 슬롯이 꽉 참 | 바로 발동하되 피해 80% (반올림, 최소 1) |
| 마무리 단어 SHIFT | 슬롯을 거치지 않고 바로 발동 |
| 페이즈가 끝나거나 사망해서 다시 시작 | 슬롯에 남은 블록은 사라짐 |
| 마지막 페이즈에서 SHIFT로 전환되는 순간 | 남은 블록은 사라짐(손 HP를 1 아래로 못 내려서 쓸모가 없으므로) |

- 왜: 왼쪽에서 맞추면 오른쪽에서 쏴야 하므로 두 판을 오갈 이유가 생기고, 모아 두었다가 연달아 쏘는 타격감이 생긴다.
- 블록 내구도 2: 손의 "슬롯 깨기"에 한 번 맞으면 금이 가고 흔들리며, 두 번 맞으면 사라진다.
- 슬롯 위에 서 있으면 화면 아래에 `Space: FIRE 발동`이 뜨고, 콤보가 가능한 시간이면 `(콤보 가능!)`이 붙는다.
- "글자를 두 판에 나눠 담기" 안은 쓰지 않는다. 판을 오가게 하는 장치는 이 슬롯 하나다.

| 페이즈 | 단어 (목록 순서대로 나온다) | 손 HP |
| --- | --- | --- |
| 1 | FIRE, BOLT, WIND, BEAM, NOVA | 20 |
| 2 | MAGIC, FROST, LASER, STORM, BLADE, FLAME | 25 |
| 3 | COMET, BLAZE, VORTEX, ROCKET, DRAGON | 25 |
| 마무리 | **SHIFT** (마지막 페이즈에서 손 HP ≤ 5가 되면 강제 전환) | - |

- **한 단어에 같은 글자는 한 번만.** 판마다 글자가 하나씩뿐이라 BOMB, ARROW 같은 단어는 한 줄로 맞출 수 없다. 단어 목록 검사(`checkWordList`)가 이것과 6글자 상한을 검사한다.
- 단어별 마법 연출(`attackPatterns.json`의 `spells`):

| 연출 | 단어 | 모양 |
| --- | --- | --- |
| fireball | FIRE, FLAME, COMET, BLAZE | 꼬리 달린 불덩이 → 폭발 |
| dragon | DRAGON | 불덩이 3개 연속 → 큰 폭발 |
| rocket | ROCKET | 연기 꼬리 미사일 → 큰 폭발 |
| bolt | BOLT, STORM | 하늘에서 번개(1개/3개) + 화면 번쩍 |
| beam | BEAM, LASER | 굵은 광선 / 가는 광선 3줄 |
| gust | WIND, VORTEX | 회오리 고리 |
| nova / sparkle | NOVA, MAGIC | 별이 날아가 링으로 터짐 / 별 여러 개 |
| shards | FROST | 얼음 조각 → 결정 |
| slash | BLADE | 칼날 3번 베기 |
| shift | SHIFT | ⇧ 화살표 → 화면 전체 파란 충격파 |

- 화면 안내 — **위치는 계속 보여 주지 않고 깜빡인다(5차 추가):** 도망다니면서 글자를 찾게 만들기 위해서다.
  - 4초마다 1초 동안 두 번 깜빡인다. 그동안만 판에 단어 글자(노랑), 가장 많이 맞춘 자리(노란 점선 슬롯), 제자리에 맞은 글자(초록)가 보인다. 나머지 시간에는 판이 평범한 키보드다.
  - 새 단어가 나오면 바로 한 번 깜빡이고 주기를 처음부터 센다.
  - 줄을 돌려서 제자리 글자가 늘면 그 칸만 0.5초 초록으로 번쩍인다(내가 맞췄다는 확인).
  - 화면 위 목표 단어에는 제자리 글자를 초록으로 늘 보여 주고, `3/4글자`처럼 진행도만 적는다(어느 줄인지는 안 알려 줌).
  - 주기와 깜빡이는 시간은 `hintInterval`, `hintDuration`(디버그 슬라이더).
- 마무리 직전 손 HP는 SHIFT 외 단어로 1 아래로 떨어지지 않는다.

## 6. 손(커서)의 공격
모든 공격은 예고(빨간 테두리 + 깜빡임) 후 발동한다. 범위 안에 있으면 피해 1. **키의 글자는 바꾸지 않는다.**

| 공격 | 동작 | 판 변화 | 페이즈 |
| --- | --- | --- | --- |
| 클릭 / 더블클릭 | 플레이어 칸 | 없음 | 1~3 |
| 조준 돌진 | 플레이어를 향해 관통 | 없음 | 1~3 |
| 소환 탄 | 줄을 따라 이동 | 없음 | 1~3 |
| **줄 섞기**(튕기기) | 줄 한쪽 끝에서 튕겨 1칸 돌림. 그 줄의 플레이어는 피해 + 같이 밀림 | 한 줄 1칸 | 1~3, 쿨다운 7초 |
| 추적 내려찍기 | 그림자가 1.5초 따라다니다 2x2 | 없음 | 2~3 |
| 둘레 돌진 | 줄 바깥쪽을 따라 관통 | 없음 | 2~3 |
| 드래그 선택 | 플레이어 주변 사각형 | 없음 | 2~3 |
| 전체 공격 | 플레이어 키보드 전체, 예고 약 2초 → SHIFT 칸으로 피하라는 신호 | 없음 | 3 |
| **슬롯 깨기** | 공격 블록이 든 슬롯을 친다(어느 판이든, 플레이어가 없어도). 블록 내구도 −1, 0이면 사라짐. 슬롯 위의 플레이어도 맞음 | 없음 | 1~3, 쿨다운 6초 |

- AI: 상황 점수(플레이어 위치·이동·체류 시간, 손 위치, 쿨다운) → 상위 후보 가중치 랜덤. 같은 공격 연속 금지.
- 줄 섞기는 플레이어가 2글자 이상 맞춘 줄을 **가로지르는** 줄을 노리면 가산점(맞춘 글자 하나가 빠진다).
- 손이 섞다가 우연히 단어가 맞춰지면 그것도 완성으로 친다.
- 블록이 쌓일수록: 슬롯 깨기는 그 판에 쌓인 블록 수 × 3점 가산. 플레이어가 서 있는 판에 블록이 있으면 공격 간격이 블록당 15% 짧아진다(쏘러 온 플레이어를 더 압박).
- 공정성: 공격 확정 전 BFS. 걸음 수 = floor((예고 − 반응 0.25초) / 이동 반복 간격) 안에 안전한 칸(쓸 수 있는 SHIFT 칸 포함)이 없으면 그 공격은 안 쓴다.

## 7. 수치 (시작값, 조절 가능하게)
예고 0.7초, 손 속도 560px/초, **공격 간격 2.4초**, 플레이어 HP 5, 피격 무적 1초, 줄 돌리기 반복 0.24초, 마법 맞은 손 멈춤 0.8초.
공격 슬롯: 넘침 피해 80%(`overflowMul`), 콤보 시간 1.5초(`comboWindow`), 콤보 보너스 +50%(`comboBonus`), 블록 내구도 2(`blockHp`), 블록당 공격 간격 −15%(`blockAggro`).
페이즈 배율: 2페이즈 속도 ×1.1 · 간격 ×0.9 · 예고 ×0.95, 3페이즈 속도 ×1.2 · 간격 ×0.8 · 예고 ×0.9.
사망 시 현재 페이즈 처음부터(판도 시작 배치로), 손 HP는 잃은 만큼의 **절반만** 회복.

**Unity에서 바꾸거나 더한 값 (11/20~21, `Assets/Data/AttackPatterns.asset`, 웹 JSON에는 없음)**
- 손 HP: 페이즈 1 **8** · 2 **13** · 3 **14** (웹 20/25/25). 페이즈당 단어 2~3개로 한 판 4~6분 목표. 페이즈 1 공격 간격 배율 **1.25**(2.4초 → 3.0초).
- 입력 쉬는 시간: 이동 `MoveDelay` 0.1초, 줄 돌리기 `RotateDelay` 0.2초(쉬는 동안 누른 입력 하나는 예약).
- 페이즈 전환: 손 퇴장 `PhaseClearTime` 1.5초 → 배너 `PhaseIntroTime` 2초 → 첫 공격 대기 `PhaseFirstAttackDelay` 1초. 마무리 SHIFT 배너 `FinisherIntroTime` 1.5초.
- 게임 시작·사망 후 재시작 첫 공격 대기 `StartFirstAttackDelay` 3초.
- 연습 구간: 새 판의 첫 단어(FIRE)는 손이 공격하지 않고 힌트가 계속 켜져 있으며, 첫 블록을 쏘면 끝난다.
- 사망해도 슬롯 블록은 유지, 쓰러짐 화면에 원인 표시.

- 판 사이 간격 2칸(웹 2.72칸, 픽셀 화면에 맞춤).
